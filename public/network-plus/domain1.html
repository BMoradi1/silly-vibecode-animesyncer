1.1 The OSI Model

The Open Systems Interconnection (OSI) model is a conceptual framework created by the International Organization for Standardization (ISO) in 1984. It standardizes how different networking systems communicate by dividing the communication process into seven distinct layers. Each layer has a specific function and communicates with the layers directly above and below it.

Understanding the OSI model is absolutely essential for the Network+ exam. You need to know every layer, the protocols that operate at each layer, the data unit names, and how data flows through the model during encapsulation and de-encapsulation.

The Seven Layers

Mnemonic (Top to Bottom): All People Seem To Need Data Processing Application, Presentation, Session, Transport, Network, Data Link, Physical. This mnemonic reads from Layer 7 down to Layer 1.
Mnemonic (Bottom to Top): Please Do Not Throw Sausage Pizza Away Physical, Data Link, Network, Transport, Session, Presentation, Application. This mnemonic reads from Layer 1 up to Layer 7. Many students find this version easier to remember.
Layer # Layer Name PDU Function Key Protocols / Tech Devices
7 Application Data Provides network services directly to end-user applications. Handles high-level APIs, resource sharing, and remote file access. HTTP, HTTPS, FTP, SMTP, DNS, DHCP, SNMP, Telnet, SSH, POP3, IMAP, LDAP Firewalls (L7), Load Balancers
6 Presentation Data Translates data formats between the application and network. Handles encryption/decryption, compression, and character encoding. SSL/TLS, JPEG, GIF, PNG, MPEG, ASCII, EBCDIC —
5 Session Data Establishes, manages, and terminates sessions (dialogues) between applications. Controls simplex, half-duplex, and full-duplex communication. NetBIOS, PPTP, RPC, SCP —
4 Transport Segment (TCP) / Datagram (UDP) Provides reliable or unreliable end-to-end data delivery. Handles segmentation, flow control, error recovery, and port addressing. TCP, UDP Firewalls (L4)
3 Network Packet Handles logical addressing (IP) and routing. Determines the best path for data to travel across networks. IP (IPv4, IPv6), ICMP, IGMP, IPsec, OSPF, EIGRP, BGP, RIP Router, Layer 3 Switch
2 Data Link Frame Provides node-to-node data transfer and handles MAC addressing, error detection (CRC), and media access control. Divided into LLC (upper) and MAC (lower) sublayers. Ethernet (802.3), Wi-Fi (802.11), ARP, PPP, STP, VLANs Switch, Bridge, NIC
1 Physical Bits Transmits raw bitstream over the physical medium. Defines electrical signals, light pulses, radio frequencies, cable specifications, and physical connectors. Ethernet physical (cables), DSL, ISDN, RS-232, 802.11 radio Hub, Repeater, Cable, Modem

Encapsulation and De-encapsulation

Encapsulation is the process of wrapping data with protocol headers (and sometimes trailers) as it moves down through the OSI layers from the application to the physical layer. Each layer adds its own header information. De-encapsulation is the reverse process: as data moves up the layers at the receiving end, each layer strips off the corresponding header.

Sending Host Receiving Host ============= ============== Layer 7 Application [ DATA ] Application Layer 7 | ^ v | Layer 6 Presentation [ DATA ] Presentation Layer 6 | ^ v | Layer 5 Session [ DATA ] Session Layer 5 | ^ v | Layer 4 Transport [ L4H | DATA ] Transport Layer 4 | (Segment) ^ v | Layer 3 Network [ L3H | L4H | DATA ] Network Layer 3 | (Packet) ^ v | Layer 2 Data Link [ L2H | L3H | L4H | DATA | FCS ] Data Link Layer 2 | (Frame) ^ v | Layer 1 Physical [ 0110110101011... ] Physical Layer 1 | (Bits) ^ v | ============= Physical Medium ==================>

In the diagram above: L2H = Layer 2 Header (MAC addresses), L3H = Layer 3 Header (IP addresses), L4H = Layer 4 Header (port numbers), and FCS = Frame Check Sequence (error detection trailer added at Layer 2).

Key Concepts to Remember

  • Layers 7-5 (Application, Presentation, Session) are often called the upper layers or "host layers" and deal with application-level concerns.
  • Layers 4-1 (Transport, Network, Data Link, Physical) are the lower layers or "media layers" and handle actual data transport.
  • Layer 2 sublayers: The Data Link layer is divided into LLC (Logical Link Control — interfaces with Layer 3) and MAC (Media Access Control — interfaces with Layer 1).
  • Same-layer interaction: Each layer on the sending host communicates logically with the same layer on the receiving host.
  • Adjacent-layer interaction: Each layer communicates with the layers directly above and below it on the same host.
Exam Alert The exam will ask you to identify which OSI layer a specific protocol operates at, or which PDU name corresponds to which layer. Make sure you can identify: Bits (L1), Frames (L2), Packets (L3), Segments/Datagrams (L4), and Data (L5-L7).

1.2 The TCP/IP Model

The TCP/IP model (also called the Internet Protocol Suite or DoD model) is the practical networking model that the Internet and most modern networks are built upon. Unlike the theoretical OSI model with seven layers, the TCP/IP model uses four layers. It was developed by the U.S. Department of Defense (DoD) in the 1970s, predating the OSI model.

The Four Layers

TCP/IP Layer OSI Equivalent Function Key Protocols
4. Application Layers 7, 6, 5 Combines the functions of OSI Application, Presentation, and Session layers. Provides process-to-process communication and user interfaces. HTTP, HTTPS, FTP, SSH, Telnet, SMTP, DNS, DHCP, SNMP, TFTP
3. Transport Layer 4 Provides end-to-end communication, reliability (TCP) or speed (UDP), flow control, and port-based addressing. TCP, UDP
2. Internet Layer 3 Handles logical addressing and routing. Moves packets across network boundaries from source to destination. IP (v4/v6), ICMP, ARP, IGMP
1. Network Access Layers 2, 1 Combines the functions of OSI Data Link and Physical layers. Handles the physical transmission of data on the local network segment. Ethernet, Wi-Fi (802.11), PPP, Frame Relay, ARP*

*Note: ARP operates between Layers 2 and 3 and is sometimes placed at the Internet layer or the Network Access layer depending on the reference.

TCP vs. UDP

TCP (Transmission Control Protocol) and UDP (User Datagram Protocol) are the two primary transport-layer protocols. Understanding their differences is critical for the exam.

Feature TCP UDP
Connection Type Connection-oriented Connectionless
Reliability Reliable — guarantees delivery via acknowledgments Unreliable — no delivery guarantee (best-effort)
Ordering Guarantees in-order delivery using sequence numbers No ordering guarantee
Speed Slower (overhead from handshake, ACKs, flow control) Faster (minimal overhead)
Header Size 20 bytes minimum 8 bytes
Flow Control Yes (windowing) No
Error Recovery Yes (retransmission of lost segments) No (application must handle)
PDU Name Segment Datagram

The TCP Three-Way Handshake

Before TCP can transmit data, it must establish a connection using the three-way handshake. This ensures both sides are ready to communicate and agree on initial sequence numbers.

Client Server | | | 1. SYN (seq=100) | |----------------------------------->| | | | 2. SYN-ACK (seq=300, ack=101) | |<-----------------------------------| | | | 3. ACK (seq=101, ack=301) | |----------------------------------->| | | | Connection ESTABLISHED | | Data transfer can begin | | |
  1. SYN — The client sends a SYN (synchronize) segment to the server, indicating it wants to establish a connection and providing its initial sequence number.
  2. SYN-ACK — The server responds with a SYN-ACK segment, acknowledging the client's SYN and providing its own initial sequence number.
  3. ACK — The client sends an ACK (acknowledge) segment, confirming receipt of the server's SYN-ACK. The connection is now established.

TCP Connection Termination (Four-Way Teardown)

When either side wants to close the connection, it uses a four-way teardown:

Client Server | | | 1. FIN | |----------------------------------->| | | | 2. ACK | |<-----------------------------------| | | | 3. FIN | |<-----------------------------------| | | | 4. ACK | |----------------------------------->| | | | Connection CLOSED | | |

Connection-Oriented vs. Connectionless

  • Connection-oriented (TCP): A session is established before data is sent. Think of it like a phone call — you dial, wait for an answer, then talk. Guarantees delivery and order.
  • Connectionless (UDP): No session is established. Think of it like sending a letter — you drop it in the mailbox and hope it arrives. Faster but no guarantees.
Exam Tip Remember: TCP = "Trustworthy Communication Protocol" (reliable), UDP = "Unreliable Datagram Protocol" (fast but best-effort). The exam loves to ask which protocol a given service uses and why.

1.3 Common Ports & Protocols

Port numbers are used by the Transport layer (Layer 4) to direct traffic to the correct application or service on a host. Ports range from 0 to 65,535 and are divided into three ranges:

  • Well-Known Ports (0-1023) — Reserved for common protocols and services assigned by IANA.
  • Registered Ports (1024-49151) — Assigned by IANA for specific applications upon request.
  • Dynamic/Ephemeral Ports (49152-65535) — Used temporarily by client applications for outbound connections.
Memorization Strategy You must memorize these ports for the exam. Group them by function: file transfer (FTP, TFTP, SMB), email (SMTP, POP3, IMAP), web (HTTP, HTTPS), remote access (SSH, Telnet, RDP), directory (LDAP, LDAPS), and management (SNMP, syslog, NTP). 1.4 IP Addressing & Subnetting

IP addressing is one of the most heavily tested topics on the Network+ exam. You need to understand IPv4 address classes, private vs. public ranges, CIDR notation, subnet masks, subnetting calculations, and the fundamentals of IPv6.

IPv4 Address Classes

IPv4 addresses are 32 bits long, written as four octets in dotted decimal notation (e.g., 192.168.1.1). Classful addressing divides the address space into five classes:

Class First Octet Range Default Subnet Mask CIDR Networks Hosts per Network Purpose
A 1 – 126 255.0.0.0 /8 126 16,777,214 Large networks
B 128 – 191 255.255.0.0 /16 16,384 65,534 Medium networks
C 192 – 223 255.255.255.0 /24 2,097,152 254 Small networks
D 224 – 239 N/A N/A N/A N/A Multicast
E 240 – 255 N/A N/A N/A N/A Experimental / Reserved
Special Addresses 127.0.0.0/8 is reserved for loopback (localhost). 127.0.0.1 is the standard loopback address. The range 127.x.x.x is not assignable to hosts, which is why Class A starts at 1 and ends at 126.

Private IP Address Ranges (RFC 1918)

These addresses are not routable on the public Internet and are used within private networks. NAT is used to translate them to public addresses for Internet access.

Class Private Range CIDR Notation Number of Addresses
A 10.0.0.0 – 10.255.255.255 10.0.0.0/8 16,777,216
B 172.16.0.0 – 172.31.255.255 172.16.0.0/12 1,048,576
C 192.168.0.0 – 192.168.255.255 192.168.0.0/16 65,536

APIPA (Automatic Private IP Addressing)

When a device is configured to obtain an IP address via DHCP but cannot reach a DHCP server, it will automatically assign itself an address in the 169.254.0.0/16 range (169.254.0.1 – 169.254.255.254). This is called APIPA or a link-local address in IPv4. APIPA addresses allow communication only on the local network segment — they are not routable.

Exam Alert If you see an address in the 169.254.x.x range on the exam, it almost always indicates a DHCP failure. The device could not obtain an address from a DHCP server.

Subnetting Step-by-Step

Subnetting is the process of dividing a large network into smaller, more manageable subnetworks. Here is the method:

Example: Subnet 192.168.10.0/26

  1. Determine the subnet mask: /26 = 255.255.255.192. The "interesting octet" is the 4th octet (192 in binary = 11000000).
  2. Calculate the block size: 256 - 192 = 64. Subnets increment by 64 in the 4th octet.
  3. List the subnets: 192.168.10.0, 192.168.10.64, 192.168.10.128, 192.168.10.192 (4 subnets).
  4. Calculate hosts per subnet: 2^6 - 2 = 62 usable hosts (6 host bits, minus network and broadcast).
  5. Determine ranges:
    • Subnet 1: Network 192.168.10.0, Hosts .1 - .62, Broadcast .63
    • Subnet 2: Network 192.168.10.64, Hosts .65 - .126, Broadcast .127
    • Subnet 3: Network 192.168.10.128, Hosts .129 - .190, Broadcast .191
    • Subnet 4: Network 192.168.10.192, Hosts .193 - .254, Broadcast .255
Quick Subnetting Formula Number of subnets = 2^(borrowed bits). Number of hosts per subnet = 2^(host bits) - 2. The block size (also called the "magic number") = 256 - subnet mask value in the interesting octet.

IPv6 Address Types

  • Global Unicast (2000::/3) — Equivalent to IPv4 public addresses. Globally routable on the Internet. Begin with 2000:: through 3FFF::.
  • Link-Local (FE80::/10) — Automatically assigned to every IPv6-enabled interface. Used for communication on the local link only (not routable). Always starts with FE80::. Required for IPv6 operation.
  • Unique Local (FC00::/7) — Equivalent to IPv4 private addresses (RFC 1918). Routable within an organization but not on the Internet. Typically uses FD00::/8.
  • Multicast (FF00::/8) — Sends packets to multiple destinations simultaneously. Replaces IPv4 broadcast. Examples: FF02::1 (all nodes), FF02::2 (all routers).
  • Anycast — Assigned to multiple interfaces; packets are routed to the nearest one. Uses the same address format as unicast. Used for load balancing and redundancy (e.g., DNS root servers).
  • Loopback — ::1 (equivalent to IPv4's 127.0.0.1).
  • Unspecified — :: (equivalent to IPv4's 0.0.0.0). Used when a device does not yet have an address.
IPv6 Shortening Rules 1. Leading zeros in each group can be removed: 2001:0db8:0000:0001 becomes 2001:db8:0:1. 2. One consecutive group of all-zero sections can be replaced with :: (only once per address): 2001:db8:0:0:0:0:0:1 becomes 2001:db8::1.

1.5 Network Types & Topologies

Network Types by Geographic Scope

Acronym Full Name Scope Description
PAN Personal Area Network Within reach of a person (~10m) Bluetooth, USB connections between personal devices. Example: phone to wireless earbuds.
LAN Local Area Network Single building or campus High-speed network in a limited area. Uses Ethernet and/or Wi-Fi. Most common network type.
WLAN Wireless Local Area Network Same as LAN (wireless) LAN using Wi-Fi (802.11 standards) instead of cables. Connected to wired LAN via access points.

Physical Topologies

A physical topology describes the actual physical layout of cables, devices, and connections in a network.

Topology Description Advantages Disadvantages
Star All devices connect to a central device (switch or hub). Most common modern LAN topology. Easy to add/remove devices; single cable failure affects only one device; easy to troubleshoot. Central device is a single point of failure; requires more cable than bus.
Mesh Every device connects to every other device. Full mesh: all devices interconnected. Partial mesh: some devices interconnected. Highest redundancy and fault tolerance; multiple paths for data. Expensive; complex cabling; formula: n(n-1)/2 links for full mesh.
Bus All devices share a single backbone cable with terminators at both ends. Legacy topology. Simple and inexpensive; easy to implement for small networks. Single cable failure brings down entire network; difficult to troubleshoot; collisions.
Ring Devices connected in a circular loop. Data travels in one direction (or both in dual ring). Used in Token Ring and FDDI. Predictable performance; no collisions (token-passing). Single break disrupts entire network (unless dual ring); difficult to reconfigure.
Hybrid Combination of two or more topologies. Example: star-bus (star topology segments connected via a bus backbone). Flexible; scalable; can be tailored to specific needs. Complex design; can be expensive.

Logical Topologies

A logical topology describes how data flows through the network, regardless of physical layout. For example, a network may be physically wired as a star (all devices connected to a switch) but logically function as a bus (Ethernet uses CSMA/CD, where all devices share the same broadcast domain). Similarly, a Token Ring network physically wired as a star uses a logical ring topology where a token is passed sequentially.

Cloud Computing Concepts

Cloud computing delivers IT resources over the Internet on a pay-as-you-go basis. The three main service models are:

Model Full Name What You Manage What Provider Manages Examples
IaaS Infrastructure as a Service OS, middleware, runtime, applications, data Virtualization, servers, storage, networking AWS EC2, Azure VMs, Google Compute Engine
PaaS Platform as a Service Applications, data OS, middleware, runtime, virtualization, servers, storage, networking AWS Elastic Beanstalk, Azure App Service, Heroku

Cloud Deployment Models

  • Public Cloud — Resources owned and operated by a third-party provider, shared among multiple tenants. Accessible over the Internet. Cost-effective and scalable. Examples: AWS, Azure, Google Cloud.
  • Private Cloud — Cloud infrastructure dedicated to a single organization. Can be on-premises or hosted by a third party. Greater control and security but higher cost.
  • Hybrid Cloud — Combines public and private cloud environments. Data and applications can move between them. Provides flexibility: keep sensitive data private while leveraging public cloud scalability.
  • Community Cloud — Shared infrastructure for organizations with common concerns (compliance, security, mission). Example: government agencies sharing a cloud platform.

Virtualization Concepts

Virtualization allows multiple virtual machines (VMs) to run on a single physical host, each with its own operating system and applications.

Hypervisor Types

Type Name Description Examples
Type 1 Bare-Metal Runs directly on the physical hardware (no host OS). Better performance and security. Used in enterprise data centers. VMware ESXi, Microsoft Hyper-V, Citrix XenServer, KVM
Type 2 Hosted Runs on top of a host operating system as an application. Easier to set up. Used for development and testing. VMware Workstation, Oracle VirtualBox, Parallels Desktop

Virtual Networking Components

  • Virtual Switch (vSwitch) — A software-based switch that connects VMs to each other and to the physical network. Operates at Layer 2, supports VLANs, and can enforce security policies.
  • Virtual NIC (vNIC) — A software-based network adapter assigned to each VM. Each vNIC has its own MAC address and can be configured with its own IP address, just like a physical NIC.
  • Virtual Router — Software-based router that routes traffic between virtual network segments.
  • Virtual Firewall — Software firewall that filters traffic between VMs and virtual network segments. Can be part of the hypervisor or a dedicated virtual appliance.
Exam Tip Know that Type 1 hypervisors are more performant and secure than Type 2 because they run directly on hardware without a host OS layer. The exam may ask you to identify which hypervisor type is appropriate for a given scenario.

1.6 Network Services

DNS (Domain Name System)

DNS is the "phone book" of the Internet. It translates human-readable domain names (like www.example.com) into IP addresses (like 93.184.216.34) that computers use to communicate. DNS operates on port 53 using UDP for standard queries and TCP for zone transfers.

How DNS Resolution Works

  1. Client checks its local DNS cache for the record.
  2. If not found, client queries its configured recursive DNS resolver (usually provided by ISP or set to 8.8.8.8, 1.1.1.1, etc.).
  3. Recursive resolver checks its cache. If not found, it queries the root name servers (.).
  4. Root servers direct the resolver to the appropriate TLD name server (.com, .org, .net, etc.).
  5. TLD server directs the resolver to the authoritative name server for the domain.
  6. The authoritative server returns the IP address to the resolver, which caches it and returns it to the client.

DNS Record Types

Click each card to reveal the description:

A Record (Address)
Maps a hostname to an IPv4 address. The most common DNS record type. Example: www.example.com → 93.184.216.34
AAAA Record (Quad-A)
Maps a hostname to an IPv6 address. Same purpose as an A record but for IPv6. Example: www.example.com → 2606:2800:220:1:248:1893:25c8:1946
MX Record (Mail Exchange)
Specifies the mail server(s) responsible for receiving email for the domain. Includes a priority value (lower = higher priority). Example: example.com MX 10 mail.example.com
CNAME Record (Canonical Name)
Creates an alias that points one hostname to another hostname (not to an IP). Used for subdomains. Example: www.example.com CNAME example.com. Cannot coexist with other record types for the same name.
PTR Record (Pointer)
Used for reverse DNS lookups — maps an IP address back to a hostname. Stored in the in-addr.arpa (IPv4) or ip6.arpa (IPv6) zone. Used for email verification and logging.
NS Record (Name Server)
Identifies the authoritative DNS servers for a domain. Every domain must have at least one NS record. Example: example.com NS ns1.example.com
SOA Record (Start of Authority)
Contains administrative information about the DNS zone: primary name server, responsible person's email, serial number, refresh/retry/expire timers, and minimum TTL. Every zone has exactly one SOA record.
SRV Record (Service Locator)
Specifies the host and port for specific services. Used by applications to discover services. Format includes priority, weight, port, and target. Example: _sip._tcp.example.com SRV 10 60 5060 sipserver.example.com
TXT Record (Text)
Stores arbitrary text data associated with a domain. Commonly used for SPF (email sender verification), DKIM (email signing), DMARC (email authentication policy), and domain ownership verification.

DHCP (Dynamic Host Configuration Protocol)

DHCP automatically assigns IP addresses and other network configuration parameters (subnet mask, default gateway, DNS servers) to devices on a network. It uses UDP ports 67 (server) and 68 (client). This eliminates the need for manual IP configuration on every device.

The DORA Process

DHCP uses a four-step process known as DORA:

Client Server | | | 1. DISCOVER (broadcast) | | "Any DHCP servers out there?" | |------------------------------------->| | | | 2. OFFER (unicast or broadcast) | | "Here's an IP you can use." | |<-------------------------------------| | | | 3. REQUEST (broadcast) | | "I'd like that IP, please." | |------------------------------------->| | | | 4. ACKNOWLEDGE (unicast or bcast) | | "It's yours. Here's the config." | |<-------------------------------------| | | | Client is now configured! | | |
  1. Discover — Client broadcasts a DHCPDISCOVER message to find available DHCP servers on the network (source: 0.0.0.0, destination: 255.255.255.255).
  2. Offer — DHCP server(s) respond with a DHCPOFFER containing an available IP address and configuration parameters.
  3. Request — Client broadcasts a DHCPREQUEST indicating which offer it accepts (in case multiple servers responded).
  4. Acknowledge — The server confirms the lease with a DHCPACK, and the client configures its network interface with the assigned settings.
DHCP Lease Renewal IP addresses are leased for a specific duration. At 50% of the lease time (T1), the client attempts to renew directly with the original server. At 87.5% (T2), if renewal failed, the client broadcasts to any available DHCP server. If the lease expires, the client must restart the DORA process.
DHCP Relay Agent Since DHCP uses broadcasts, it normally only works within a single subnet. A DHCP relay agent (also called an IP helper) on a router forwards DHCP broadcasts across subnet boundaries to a centralized DHCP server. This is configured with the ip helper-address command on Cisco routers.

NAT (Network Address Translation)

NAT translates private (RFC 1918) IP addresses to public IP addresses, allowing multiple internal devices to share one or more public IP addresses for Internet access. NAT operates at Layer 3 (Network) on routers or firewalls.

NAT Type Description Use Case
Static NAT One-to-one mapping between a single private IP and a single public IP. Permanent mapping. Servers that need to be accessible from the Internet (web server, mail server). Also called "port forwarding" in home routers.
Dynamic NAT Maps private IPs to public IPs from a pool of available addresses. First-come, first-served. Mapping is temporary. When you have a pool of public addresses and want internal hosts to access the Internet without a permanent mapping.
PAT (Port Address Translation) Many-to-one NAT. Maps multiple private IPs to a single public IP using different port numbers to distinguish sessions. Also called NAT overload. Most common NAT type. Used in home routers and small businesses. Allows hundreds of devices to share one public IP.
Exam Alert PAT (NAT overload) is the most commonly tested NAT type. Understand that PAT uses unique source port numbers to track which internal device each outbound connection belongs to, allowing many devices to share a single public IP address.

NTP (Network Time Protocol)

NTP synchronizes clocks across network devices using UDP port 123. Accurate time is critical for:

  • Log correlation — Matching timestamps across devices when troubleshooting or investigating security incidents.
  • Authentication protocols — Kerberos requires clocks to be synchronized within 5 minutes.
  • Certificate validation — SSL/TLS certificates have validity periods tied to time.
  • Scheduled tasks — Backups, updates, and jobs that need to run at specific times.

NTP uses a hierarchy of strata: Stratum 0 is the reference clock (atomic clock, GPS), Stratum 1 servers connect directly to Stratum 0, Stratum 2 servers sync from Stratum 1, and so on. Lower stratum = more accurate. Maximum is Stratum 15; Stratum 16 means unsynchronized.

Domain 1 Quiz: Networking Concepts

Test your knowledge of networking concepts. Select the best answer for each question, then click Submit to check your results.

1. Which OSI layer is responsible for logical addressing and routing?

  • A. Data Link (Layer 2)
  • B. Network (Layer 3)
  • C. Transport (Layer 4)
  • D. Session (Layer 5)
The Network layer (Layer 3) handles logical addressing (IP addresses) and determines the best path (routing) for data to travel from source to destination across networks. Routers operate at this layer.

2. What is the correct order of the TCP three-way handshake?

  • A. ACK, SYN, SYN-ACK
  • B. SYN, ACK, SYN-ACK
  • C. SYN, SYN-ACK, ACK
  • D. SYN-ACK, SYN, ACK
The TCP three-way handshake follows the order: SYN (client initiates), SYN-ACK (server acknowledges and synchronizes), ACK (client confirms). This establishes a reliable connection before data transfer begins.

3. Which port is used by HTTPS?

  • A. 80
  • B. 8080
  • C. 8443
  • D. 443
HTTPS (HTTP Secure) uses TCP port 443. HTTP uses port 80. Port 8080 is a common alternative HTTP port, and 8443 is an alternative HTTPS port, but the standard well-known ports are 80 and 443 respectively.

4. A client receives an IP address of 169.254.10.5. What does this most likely indicate?

  • A. The DHCP server is unreachable, so the client assigned itself an APIPA address
  • B. The client was assigned a valid private IP address
  • C. The client has a valid public IP address
  • D. The DNS server is down
Addresses in the 169.254.0.0/16 range are APIPA (Automatic Private IP Addressing) addresses. A device assigns itself an APIPA address when it is configured to use DHCP but cannot contact a DHCP server. APIPA addresses are link-local only and do not provide Internet connectivity.

5. How many usable host addresses are available in a /28 subnet?

  • A. 16
  • B. 14
  • C. 30
  • D. 12
A /28 subnet has 4 host bits (32 - 28 = 4). Total addresses = 2^4 = 16. Usable host addresses = 16 - 2 = 14 (subtract the network address and broadcast address). The subnet mask is 255.255.255.240.

6. Which DNS record type is used to map a hostname to an IPv6 address?

  • A. A
  • B. MX
  • C. AAAA
  • D. CNAME
The AAAA (Quad-A) record maps a hostname to an IPv6 address. The A record maps a hostname to an IPv4 address. MX records specify mail servers, and CNAME records create hostname aliases.

7. Which type of NAT allows multiple internal hosts to share a single public IP address by using different port numbers?

  • A. Static NAT
  • B. Dynamic NAT
  • C. Bidirectional NAT
  • D. PAT (Port Address Translation)
PAT (Port Address Translation), also known as NAT overload, allows many internal hosts to share a single public IP address. PAT uses unique source port numbers to keep track of which internal device initiated each connection. This is the most common form of NAT used in home and small office routers.

8. Which of the following correctly describes the DHCP DORA process in order?

  • A. Discover, Offer, Request, Acknowledge
  • B. Discover, Offer, Acknowledge, Request
  • C. Demand, Offer, Reply, Acknowledge
  • D. Discover, Open, Request, Accept
DORA stands for Discover, Offer, Request, Acknowledge. The client Discovers servers via broadcast, the server Offers an IP, the client Requests that specific IP, and the server Acknowledges the lease. This is a fundamental concept for the Network+ exam.

9. A Type 1 hypervisor differs from a Type 2 hypervisor in that a Type 1 hypervisor:

  • A. Runs as an application on top of a host operating system
  • B. Runs directly on the physical hardware without a host OS
  • C. Can only run a single virtual machine at a time
  • D. Is used exclusively for desktop virtualization
A Type 1 (bare-metal) hypervisor runs directly on the physical hardware without a host operating system, providing better performance and security. Examples include VMware ESXi and Microsoft Hyper-V. A Type 2 (hosted) hypervisor runs as an application on top of an existing OS, such as VMware Workstation or VirtualBox.

10. Which of the following is a valid IPv6 link-local address?

  • A. 2001:db8::1
  • B. FF02::1
  • C. FE80::1
  • D. FC00::1
IPv6 link-local addresses always begin with FE80::/10 (in practice, FE80::). They are automatically assigned to every IPv6-enabled interface and are used for communication on the local network segment only. 2001:db8::/32 is documentation, FF02::1 is multicast (all nodes), and FC00::/7 is unique local (private).
