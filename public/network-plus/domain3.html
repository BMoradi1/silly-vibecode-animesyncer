3.1 Network Monitoring

Network monitoring is the practice of continuously observing a network for failures, performance degradation, and suspicious activity. Effective monitoring allows administrators to detect and resolve issues before they impact users, maintain service-level agreements, and plan for future capacity needs.

SNMP (Simple Network Management Protocol)

SNMP is the dominant protocol for collecting information from and configuring network devices. It uses a manager-agent architecture: a central Network Management Station (NMS) queries agents running on managed devices such as switches, routers, firewalls, and servers.

SNMP Versions

Feature SNMPv1 SNMPv2c SNMPv3
Authentication Community string (plaintext) Community string (plaintext) Username-based (HMAC-MD5 / HMAC-SHA)

Exam Alert SNMPv1 and v2c send community strings in cleartext. On the exam, if security is a concern, SNMPv3 is always the correct choice because it provides authentication, encryption, and message integrity.

Community Strings

Community strings function as passwords in SNMPv1 and v2c. There are two default types:

  • Read-Only (RO) — Typically defaults to public. Allows the NMS to query data but not change configurations.
  • Read-Write (RW) — Typically defaults to private. Allows the NMS to both read and modify device configurations.

Default community strings should always be changed in production environments because they are well known to attackers.

MIBs and OIDs

A Management Information Base (MIB) is a hierarchical database that defines every manageable object on a device. Each object is identified by a unique Object Identifier (OID), which is a numeric string like 1.3.6.1.2.1.1.3.0 (system uptime). Vendors publish custom MIB files for their devices so that NMS platforms can interpret proprietary data.

Traps vs. Polling

Method Direction Description Port
Polling NMS → Agent The NMS sends periodic Get requests to collect data from agents. Predictable but generates regular traffic overhead. UDP 161
Traps Agent → NMS The agent sends an unsolicited alert to the NMS when a predefined event occurs (e.g., link down, high CPU). Efficient but unreliable since traps use UDP with no acknowledgment. UDP 162
Informs Agent → NMS Similar to traps but include an acknowledgment mechanism. The agent retransmits if no acknowledgment is received. Introduced in SNMPv2c. UDP 162

Syslog

Syslog is a standard protocol (UDP port 514, or TCP 514 / TCP 6514 with TLS) for sending log messages from network devices to a centralized syslog server. Centralizing logs is critical for security analysis, troubleshooting, and compliance.

NetFlow, sFlow, and IPFIX

These are flow-based monitoring technologies that provide visibility into traffic patterns, application usage, and bandwidth consumption.

  • NetFlow — Developed by Cisco. Operates on routers and switches to collect IP traffic information as it enters or exits an interface. Tracks flows (defined by source/destination IP, ports, protocol, ToS, and interface). NetFlow v5 is IPv4-only; NetFlow v9 added templates and IPv6 support.
  • sFlow — An industry-standard, multi-vendor sampling protocol. Rather than tracking every packet, sFlow samples 1-in-N packets and forwards the sample to a collector. Less resource-intensive than NetFlow on high-speed interfaces.
  • IPFIX — IP Flow Information Export. Based on NetFlow v9 and standardized by the IETF. Considered the evolution of NetFlow with flexible template support and vendor-neutral design.

Bandwidth Monitoring and Interface Statistics

Monitoring tools track key interface metrics in real time:

  • Bandwidth utilization — Percentage of available link capacity in use.
  • Error counters — CRC errors, frame errors, collisions, input/output errors.
  • Discards / drops — Packets dropped by the interface, often due to buffer overflow or QoS policies.
  • Interface status — Up/down state, speed, and duplex settings.
  • Packet counts — Unicast, broadcast, and multicast packets sent and received.

Baselines and Anomaly Detection

A baseline is a snapshot of normal network behavior captured over time (typically days or weeks). Baselines establish what is "normal" for metrics like bandwidth usage, latency, CPU utilization, and connection counts. Once a reliable baseline exists, monitoring tools can detect anomalies — deviations that may indicate performance problems, misconfigurations, or security incidents.

What port does SNMP polling use?
UDP port 161 for queries (Get/Set). Traps and Informs are sent to UDP port 162.
What makes SNMPv3 more secure than v1/v2c?
SNMPv3 adds authentication (username + HMAC-MD5/SHA), encryption (DES/AES), and message integrity verification, replacing the plaintext community string model.
What is the difference between a trap and an inform?
Both are agent-initiated alerts, but traps are unacknowledged (fire-and-forget), while informs require an acknowledgment from the NMS and will retransmit if not received.

3.2 Network Documentation

Thorough documentation is the backbone of reliable network operations. Without it, troubleshooting takes longer, changes introduce more risk, and new team members struggle to get up to speed. The exam expects you to understand each documentation type and its purpose.

Network Diagrams

Network diagrams come in two main forms, each serving a distinct purpose:

Diagram Type Shows Used For
Physical Diagram Actual device locations, rack positions, cable paths, port connections, patch panels, and building/floor layouts Cabling projects, data center planning, hardware troubleshooting, facility moves
Logical Diagram IP addressing schemes, VLANs, subnets, routing domains, WAN links, and traffic flows — regardless of physical location Network design review, troubleshooting connectivity, capacity planning, security audits

Wiring Documentation and Labeling Standards

Proper cable management documentation includes:

  • Cable labels — Both ends of every cable should be labeled with a unique identifier (e.g., R1-Gi0/1_to_SW1-Gi0/24).
  • Patch panel schedules — A document mapping each patch panel port to its destination jack and the connected device port.
  • Wiring closet layouts — Diagrams showing rack elevations, power distribution, and cable pathways within MDF/IDF rooms.
  • TIA/EIA-606 standard — Defines labeling and record-keeping for telecommunications infrastructure.

IP Address Management (IPAM)

IPAM is the practice of planning, tracking, and managing IP address space across the network. IPAM tools (spreadsheets in small shops, dedicated platforms like Infoblox or phpIPAM in larger environments) track:

  • Subnet allocations and available addresses
  • Static IP assignments with device names and locations
  • DHCP scopes and reservations
  • DNS records associated with IP addresses
  • VLAN-to-subnet mappings
Exam Tip IP address conflicts are a common troubleshooting scenario. Proper IPAM practices prevent duplicate static assignments and overlapping DHCP scopes. Always verify IPAM records when diagnosing connectivity issues.

Asset Management

An asset inventory tracks every network device (routers, switches, APs, firewalls, servers, UPS units) along with:

  • Make, model, serial number, and firmware/OS version
  • Physical location (building, floor, rack, rack unit)
  • Purchase date, warranty status, and end-of-life dates
  • Assigned IP addresses and hostnames
  • License information

Change Management

Change management is a formal process to control modifications to the network infrastructure. It reduces the risk of outages caused by poorly planned changes. A typical change management workflow includes:

  1. Request — Submit a change request describing the proposed modification.
  2. Review — A Change Advisory Board (CAB) evaluates the risk, impact, and rollback plan.
  3. Approve/Deny — The CAB approves, denies, or requests modifications.
  4. Schedule — Approved changes are scheduled during a maintenance window.
  5. Implement — The change is carried out following the documented procedure.
  6. Verify — Confirm the change works as intended.
  7. Document — Update all relevant documentation (diagrams, IPAM, configs, etc.).
Key Term A rollback plan is a predefined set of steps to reverse a change and restore the previous working state. Every change request should include one before it is approved.

Standard Operating Procedures (SOPs)

SOPs are documented, step-by-step instructions for routine tasks such as adding a new switch to the network, onboarding a user, configuring a VPN tunnel, or performing a firmware upgrade. SOPs ensure consistency, reduce human error, and allow any qualified team member to execute the task.

Baseline Configurations

A baseline configuration (also called a "golden configuration") is a standardized, security-hardened device configuration template. Every new device of a given type (e.g., access switch, branch router) should start from the baseline, with minimal deviation. Baseline configs typically include: banners, SNMP settings, syslog server, NTP server, AAA settings, disabling unused ports, and applying standard ACLs.

What is the difference between a physical and logical network diagram?
A physical diagram shows actual hardware, cable paths, and locations. A logical diagram shows IP addresses, VLANs, subnets, and traffic flow regardless of physical placement.
What is the purpose of a Change Advisory Board (CAB)?
The CAB reviews proposed changes to assess risk, impact, and feasibility, then approves, denies, or requests modifications before any changes are implemented.

3.3 High Availability & Disaster Recovery

High availability (HA) is the design goal of minimizing downtime by eliminating single points of failure. Disaster recovery (DR) defines how to restore operations after a major outage or catastrophic event. Together, HA and DR ensure business continuity.

Core HA Concepts

  • Redundancy — Deploying duplicate components (links, power supplies, devices) so that a backup can take over if the primary fails.
  • Fault Tolerance — The ability of a system to continue operating without interruption when a component fails. Requires redundancy plus automatic failover.
  • Load Balancing — Distributing traffic or workloads across multiple resources (servers, links) to optimize performance and provide redundancy. Methods include round-robin, least connections, and weighted algorithms.

NIC Teaming / Bonding

NIC teaming (Windows terminology) or NIC bonding (Linux terminology) combines two or more physical network interfaces into a single logical interface. Benefits include:

  • Failover — If one NIC fails, traffic automatically shifts to the remaining NIC(s).
  • Increased throughput — Aggregate bandwidth of all member NICs (e.g., two 1 Gbps NICs = up to 2 Gbps throughput).
  • Load distribution — Traffic is spread across all active NICs.

Link Aggregation (LACP)

Link Aggregation Control Protocol (LACP), defined in IEEE 802.3ad (now 802.1AX), bundles multiple physical switch-to-switch or switch-to-server links into a single logical link. LACP provides:

  • Increased bandwidth (combined capacity of all member links)
  • Redundancy (the aggregated link survives individual member link failures)
  • Dynamic negotiation between both ends to ensure both sides agree on the aggregation
Link Aggregation (LACP) +----------+ Gi0/1 +----------+ | |=============| | | Switch A | Gi0/2 | Switch B | | |=============| | | | Gi0/3 | | | |=============| | +----------+ +----------+ 3 x 1 Gbps = 1 Logical Link (up to 3 Gbps) If one link fails, the aggregate continues at 2 Gbps

Redundant Power

Power Solution Purpose Duration
UPS (Uninterruptible Power Supply) Provides battery backup during power loss; conditions power to prevent surges/sags Minutes to ~1 hour (enough to gracefully shut down or until generator starts)

Clustering and Failover

Clustering groups multiple devices or servers to act as a single system. If one node fails, another node takes over the workload. Types include:

  • Active/Passive (Failover) — One node handles traffic while the standby monitors. The standby takes over only when the active node fails. Simple but the standby sits idle.
  • Active/Active — All nodes handle traffic simultaneously. If one fails, the remaining nodes absorb its load. More efficient but more complex to configure.

First Hop Redundancy Protocols (FHRPs)

FHRPs provide gateway redundancy by allowing multiple routers to share a single virtual IP address as the default gateway. If the active router fails, a standby router takes over the virtual IP seamlessly.

Protocol Full Name Standard Key Details
HSRP Hot Standby Router Protocol Cisco proprietary Active/standby model. One active router, one or more standby routers. Uses priority to elect active. Virtual MAC: 0000.0c07.acXX.
VRRP Virtual Router Redundancy Protocol IEEE / IETF open standard (RFC 5798) Master/backup model. Similar to HSRP but vendor-neutral. Uses priority to elect master. Virtual MAC: 0000.5e00.01XX.
GLBP Gateway Load Balancing Protocol Cisco proprietary Provides both redundancy and load balancing. Multiple routers actively forward traffic for the same virtual IP using different virtual MACs.

Exam Note HSRP and GLBP are Cisco proprietary. VRRP is the open standard. The exam may test whether you can identify which protocol is vendor-specific vs. vendor-neutral.

SLA Concepts

A Service Level Agreement (SLA) is a contract between a service provider and customer that defines measurable performance metrics and guarantees, including:

  • Uptime guarantees — Often expressed as "nines" (99.9% = 8.76 hours downtime/year; 99.99% = 52.6 minutes/year; 99.999% = 5.26 minutes/year).
  • Mean Time To Repair (MTTR) — Average time to restore service after a failure.
  • Mean Time Between Failures (MTBF) — Average operational time between failures.
  • Response and resolution time commitments

RPO and RTO

Metric Definition Question It Answers
RPO (Recovery Point Objective) The maximum acceptable amount of data loss measured in time "How much data can we afford to lose?" (e.g., RPO of 1 hour means you need backups at least every hour)
RTO (Recovery Time Objective) The maximum acceptable time to restore service after a disaster "How quickly must we be back online?" (e.g., RTO of 4 hours means systems must be operational within 4 hours)
Remember RPO looks backward (how much past data can we lose?). RTO looks forward (how quickly must we recover?). A lower RPO requires more frequent backups. A lower RTO requires faster recovery mechanisms (hot sites, automated failover).

Multipathing

Multipathing provides multiple physical paths between a server and its storage (typically in SAN environments). If one path fails, the server continues to access storage over the remaining paths. Multipathing can also load-balance I/O across paths for improved performance.

What is the difference between active/passive and active/active failover?
In active/passive, only one node processes traffic while the other waits on standby. In active/active, all nodes process traffic simultaneously, and surviving nodes absorb the failed node's load.
Which FHRP is the open standard?
VRRP (Virtual Router Redundancy Protocol) is the open standard defined in RFC 5798. HSRP and GLBP are Cisco proprietary.
What does 99.999% uptime ("five nines") allow in annual downtime?
Approximately 5.26 minutes of downtime per year.

3.4 Backup & Recovery

Backup and recovery strategies protect organizations from data loss due to hardware failures, ransomware, accidental deletion, or natural disasters. Choosing the right backup type and recovery site depends on RPO, RTO, and budget constraints.

Backup Types

Backup Type What It Backs Up Speed (Backup) Speed (Restore) Storage Used Archive Bit
Full All selected data, every time Slowest Fastest (single set needed) Most Clears
Incremental Only data changed since the last backup of any type Fastest Slowest (need full + all incrementals) Least Clears
Differential All data changed since the last full backup Medium Medium (need full + latest differential) Medium (grows over time) Does NOT clear
Backup Comparison Over a Week (Full on Sunday) Sunday: FULL backup (all data) | Monday: Incremental: changes since Sunday (small) Differential: changes since Sunday (small) | Tuesday: Incremental: changes since Monday only (small) Differential: changes since Sunday (growing) | Wednesday: Incremental: changes since Tuesday only (small) Differential: changes since Sunday (larger) RESTORE on Wednesday failure: Incremental: Full + Mon-inc + Tue-inc + Wed-inc (4 sets) Differential: Full + Wed-diff (2 sets)
Exam Alert The key difference: Incremental backs up changes since the last backup of any type (and clears the archive bit). Differential backs up all changes since the last full backup (and does NOT clear the archive bit). This distinction is heavily tested.

The 3-2-1 Backup Rule

An industry best practice for data protection:

  • 3 copies of your data (1 primary + 2 backups)
  • 2 different storage media types (e.g., local disk + tape, or disk + cloud)
  • 1 copy stored offsite (protects against site-level disasters like fire or flood)

Backup Rotation Schemes

Grandfather-Father-Son (GFS) is a common rotation scheme:

  • Son = Daily backups (incremental or differential), rotated weekly
  • Father = Weekly full backups, rotated monthly
  • Grandfather = Monthly full backups, retained for a year or longer

GFS balances storage costs with retention depth, ensuring you can recover recent data granularly and older data at weekly or monthly intervals.

Recovery Sites

Site Type Infrastructure Data Recovery Time Cost
Cold Site Basic facility (power, cooling, space) but no equipment pre-installed None — must be shipped and restored Days to weeks Lowest
Warm Site Facility with some hardware pre-installed; may need configuration Partial or periodic replication Hours to days Moderate
Hot Site Fully equipped, mirror of production environment, ready to go Real-time or near-real-time replication Minutes to hours Highest
Exam Tip A cloud site is increasingly common and operates similarly to a hot site but leverages cloud infrastructure. The exam may also mention it as a recovery option.

Snapshots

A snapshot captures the state of a virtual machine or storage volume at a specific point in time. Snapshots are not true backups (they typically depend on the original data), but they allow rapid rollback if a change causes problems. Best practice: take a snapshot before applying patches or making major config changes, then delete it once stability is confirmed.

Data Replication

  • Synchronous replication — Data is written to both primary and remote storage simultaneously. Zero data loss (RPO = 0) but adds latency and requires low-latency links.
  • Asynchronous replication — Data is written to the primary first, then replicated to the remote site after a short delay. Lower latency impact but some data loss is possible (RPO > 0).

Recovery Procedures and Verification

A backup is only as good as your ability to restore from it. Critical practices include:

  • Regular restore testing — Periodically perform test restores to verify backup integrity and validate recovery procedures.
  • Documented recovery procedures — Step-by-step instructions for restoring from each backup type and failover to recovery sites.
  • Backup verification — Check logs for errors, verify file counts and checksums, and confirm backup completion.
  • Tabletop exercises — Walk through disaster scenarios with the team to identify gaps in recovery plans without actually performing a failover.
To restore from incremental backups, what do you need?
The last full backup plus every incremental backup taken since that full. This makes incremental restores the slowest but the backup process itself the fastest.
What does the 3-2-1 rule mean?
Keep 3 copies of data, on 2 different media types, with 1 copy stored offsite.
What is the difference between a cold site and a hot site?
A cold site is an empty facility with just power and cooling (days to recover). A hot site is a fully equipped mirror of production with real-time data replication (minutes to recover). Hot sites cost significantly more.

3.5 Performance Metrics & Optimization

Understanding the key metrics that define network performance is essential for both daily operations and the exam. This section covers the core measurements and the Quality of Service (QoS) mechanisms used to optimize traffic.

Key Performance Metrics

Metric Definition Typical Concern
Bandwidth The maximum theoretical data transfer capacity of a link (e.g., 1 Gbps). It is a measure of capacity, not actual speed. Insufficient bandwidth causes congestion during peak usage.
Throughput The actual amount of data successfully transferred per unit of time. Always less than or equal to bandwidth due to overhead, errors, and congestion. Low throughput despite high bandwidth indicates a problem (errors, congestion, misconfiguration).
Latency The time it takes for a packet to travel from source to destination (measured in milliseconds). Includes propagation, serialization, processing, and queuing delays. High latency degrades real-time applications (VoIP, video conferencing).
Jitter The variation in latency between consecutive packets. If packets arrive at inconsistent intervals, the receiving application struggles to reassemble them smoothly. VoIP and video are very sensitive to jitter. A jitter buffer can compensate for small variations.
Packet Loss The percentage of packets that fail to reach their destination. Causes include congestion, faulty hardware, or errors on the link. Even 1-2% packet loss can severely degrade VoIP quality. TCP retransmits lost packets; UDP does not.
Key Distinction Bandwidth is the theoretical maximum capacity of a pipe (like the diameter of a water pipe). Throughput is how much water actually flows through. You can have a 1 Gbps link (bandwidth) but only achieve 600 Mbps throughput due to overhead, congestion, or errors.

Quality of Service (QoS)

QoS is a set of techniques for managing network resources to prioritize certain traffic types over others. Without QoS, all traffic is treated equally (best effort), which can cause latency-sensitive traffic like VoIP to suffer during congestion.

Traffic Classification and Marking

Before QoS policies can act on traffic, packets must be identified and marked:

  • CoS (Class of Service) — Operates at Layer 2. Uses the 3-bit Priority Code Point (PCP) field in the 802.1Q VLAN tag. Values range from 0 (best effort) to 7 (highest priority). Only works on tagged (trunked) links.
  • DSCP (Differentiated Services Code Point) — Operates at Layer 3. Uses 6 bits of the IP header's ToS (Type of Service) field, providing 64 possible values (0-63). DSCP markings persist across routed networks, making DSCP the preferred marking method.

0 (BE)Best Effort (Default)General data traffic

Traffic Shaping vs. Traffic Policing

Mechanism Action on Excess Traffic Effect Where Used
Traffic Shaping Buffers (delays) excess packets and sends them later when bandwidth is available Smooths traffic to conform to a rate limit; introduces additional latency Typically outbound on WAN interfaces
Traffic Policing Drops or re-marks excess packets immediately Strictly enforces a rate limit; can cause packet loss if traffic exceeds the limit Typically inbound or at network boundaries
Exam Tip Traffic shaping = buffers and delays (smoother, adds latency). Traffic policing = drops excess (stricter, causes loss). Shaping is generally used on outbound traffic; policing on inbound.

Congestion Management

When a link is congested, queuing algorithms determine which packets are sent first:

  • FIFO (First In, First Out) — Default; no prioritization. All packets treated equally in a single queue.
  • Weighted Fair Queuing (WFQ) — Allocates bandwidth proportionally among flows. Low-volume flows get priority over high-volume flows.
  • Class-Based Weighted Fair Queuing (CBWFQ) — Extends WFQ by allowing administrators to define traffic classes with guaranteed bandwidth minimums.
  • Low Latency Queuing (LLQ) — Adds a strict priority queue to CBWFQ for delay-sensitive traffic like VoIP. The priority queue is always served first.

WAN Optimization

WAN optimization techniques reduce bandwidth consumption and improve application performance over slow or expensive WAN links:

  • Deduplication — Identifies and eliminates redundant data patterns across transfers, sending only unique byte sequences.
  • Compression — Reduces the size of data in transit using algorithms like LZ or deflate.
  • Protocol optimization — Reduces the "chattiness" of protocols like CIFS/SMB and HTTP by locally acknowledging requests and batching operations.
  • Caching — Stores frequently accessed content locally so subsequent requests are served without traversing the WAN.

CDN (Content Delivery Network)

A CDN is a geographically distributed network of proxy servers that cache and deliver content from locations close to end users. CDNs reduce latency, offload traffic from the origin server, and improve availability. Examples include Cloudflare, Akamai, and AWS CloudFront.

What DSCP value is used for VoIP bearer traffic?
DSCP 46, which maps to the Expedited Forwarding (EF) Per-Hop Behavior. EF provides low latency, low jitter, and low packet loss treatment.
What is the difference between traffic shaping and policing?
Shaping buffers excess traffic and releases it at a controlled rate (adds latency but avoids drops). Policing drops or re-marks packets that exceed the configured rate (no buffering, may cause packet loss).

3.6 Organizational Policies

Network operations exist within a framework of organizational policies and procedures. These policies govern how employees, contractors, and systems interact with the network. The exam tests your ability to identify the correct policy for a given scenario.

Acceptable Use Policy (AUP)

An AUP defines what users are and are not allowed to do on the organization's network and IT resources. It typically covers:

  • Permitted use of internet, email, and company devices
  • Prohibited activities (illegal downloads, personal business, accessing inappropriate content)
  • Consequences for violations
  • Monitoring disclosure (informing users their activity may be monitored)

Employees typically sign the AUP during onboarding.

Password Policies

Password policies define the minimum requirements for authentication credentials:

  • Complexity requirements — Minimum length, mix of uppercase, lowercase, numbers, and special characters
  • Expiration / rotation — How often passwords must be changed (note: modern guidance like NIST 800-63B de-emphasizes forced rotation)
  • Account lockout — Number of failed attempts before an account is locked
  • Password history — Prevents reuse of recent passwords
  • Multi-factor authentication (MFA) — Requiring a second factor (something you have or are) in addition to the password

BYOD (Bring Your Own Device) Policies

BYOD policies govern the use of personal devices (smartphones, laptops, tablets) on the corporate network. Key considerations:

  • Which devices and operating systems are permitted
  • Required security controls (MDM enrollment, encryption, screen lock, antivirus)
  • Network segmentation (placing BYOD devices on a separate VLAN/SSID)
  • Data ownership and remote wipe capabilities
  • Privacy boundaries between personal and corporate data

Remote Access Policies

These policies define the rules for connecting to the corporate network from external locations:

  • Approved remote access methods (VPN, virtual desktop, SSH)
  • Required security posture (up-to-date OS, active antivirus, personal firewall)
  • MFA requirements for remote sessions
  • Restrictions on split tunneling
  • Session timeout and idle disconnect settings

Security Policies

Overarching security policies establish the organization's security posture and serve as the foundation for all other security-related documents. They define:

  • Information classification levels (public, internal, confidential, restricted)
  • Access control principles (least privilege, need-to-know)
  • Physical security requirements
  • Encryption requirements for data at rest and in transit
  • Audit and logging requirements

Onboarding and Offboarding Procedures

Safety Procedures

  • ESD (Electrostatic Discharge) prevention — Use anti-static wrist straps, ESD mats, and grounded workstations when handling sensitive electronics to prevent static damage to components.
  • Proper lifting techniques — Bend at the knees, keep the back straight, and use equipment carts or ask for help when moving heavy items like servers, UPS units, or switches.
  • Electrical safety — De-energize circuits before working on them, use lockout/tagout (LOTO) procedures, and be aware of high-voltage components in UPS and PDU systems.
  • Material Safety Data Sheets (MSDS/SDS) — Documentation for chemical hazards (e.g., battery acid in UPS, toner cartridges). Must be accessible to all employees.

Key Agreements and Plans

Document Purpose
NDA (Non-Disclosure Agreement) Legal contract preventing employees or contractors from sharing confidential information with unauthorized parties.
SLA (Service Level Agreement) Defines measurable service performance targets between a provider and customer (uptime, response time, MTTR).
MOU (Memorandum of Understanding) A non-binding agreement between parties outlining mutual intentions. Less formal than an SLA.
Incident Response Plan Documented procedures for detecting, containing, eradicating, and recovering from security incidents. Defines roles, escalation paths, and communication procedures.

Data Loss Prevention (DLP)

DLP systems monitor and control data movement to prevent sensitive information from leaving the organization. DLP can operate at multiple levels:

  • Network DLP — Monitors data in transit across the network (email, web uploads, file transfers).
  • Endpoint DLP — Monitors and controls data on user devices (copy to USB, print, screenshot).
  • Cloud DLP — Monitors data stored in and transferred to cloud services.

DLP policies can be configured to detect credit card numbers, Social Security numbers, medical records, and other sensitive data patterns, then block, quarantine, or alert on the transfer.

Compliance Frameworks

Framework Full Name Applies To Focus
GDPR General Data Protection Regulation Any organization handling personal data of EU residents Data privacy, consent, right to erasure, breach notification within 72 hours
HIPAA Health Insurance Portability and Accountability Act Healthcare providers, insurers, business associates in the US Protection of PHI (Protected Health Information), requires encryption, audit controls, access restrictions

Exam Note You do not need to memorize every detail of these compliance frameworks, but you should know which framework applies to a given scenario. GDPR = EU personal data. HIPAA = US healthcare data. PCI-DSS = credit card data.
What is an Acceptable Use Policy (AUP)?
A document that defines the permitted and prohibited uses of an organization's network and IT resources by its users. It is typically signed during onboarding.
Which compliance framework governs credit card data?
PCI-DSS (Payment Card Industry Data Security Standard). It applies to any organization that stores, processes, or transmits cardholder data.
What is DLP and what are its three deployment types?
DLP (Data Loss Prevention) monitors and controls data movement to prevent sensitive information from leaving the organization. It can be deployed as Network DLP (in transit), Endpoint DLP (on devices), and Cloud DLP (in cloud services).

Domain 3 Quiz — Network Operations

Test your knowledge of network monitoring, documentation, HA/DR, backups, performance, and organizational policies. Select the best answer for each question.

1. Which version of SNMP provides authentication, encryption, and message integrity?

  • SNMPv1
  • SNMPv2c
  • SNMPv3
  • SNMPv2p
SNMPv3 uses the User-based Security Model (USM) providing authentication (HMAC-MD5/SHA), encryption (DES/AES), and message integrity. SNMPv1 and v2c only use community strings sent in cleartext.

2. A network administrator needs to restore a server after a failure. The backup strategy uses a full backup on Sunday and incremental backups Monday through Friday. The failure occurs on Thursday morning. Which backups are needed?

  • Sunday full + Wednesday incremental only
  • Sunday full + Monday, Tuesday, and Wednesday incrementals
  • Sunday full only
  • Wednesday incremental only
Incremental backups only capture changes since the last backup of any type. To restore, you need the last full backup plus every incremental since then: Sunday full + Monday, Tuesday, and Wednesday incrementals.

3. What is syslog severity level 0?

  • Debugging
  • Warning
  • Informational
  • Emergency
Syslog severity level 0 is Emergency (system unusable), the most critical level. Level 7 (Debugging) is the least severe. Remember: lower number = higher severity.

4. Which first hop redundancy protocol is an open standard?

  • VRRP
  • HSRP
  • GLBP
  • STP
VRRP (Virtual Router Redundancy Protocol) is the open standard (RFC 5798). HSRP and GLBP are both Cisco proprietary. STP is a spanning tree protocol, not an FHRP.

5. An organization needs the fastest possible recovery time and can afford the highest cost. Which disaster recovery site type should they implement?

  • Cold site
  • Warm site
  • Hot site
  • Mobile site
A hot site is a fully equipped mirror of the production environment with real-time data replication. It provides the fastest recovery time (minutes to hours) but at the highest cost.

6. Which QoS mechanism buffers excess traffic and sends it later at a controlled rate rather than dropping it?

  • Traffic policing
  • Traffic shaping
  • Traffic classification
  • Traffic mirroring
Traffic shaping buffers excess traffic and releases it at a controlled rate, smoothing bursts. Traffic policing drops or re-marks excess traffic immediately without buffering.

7. A departing employee's access should be handled according to which procedure?

  • Onboarding
  • Change management
  • Incident response
  • Offboarding
Offboarding procedures handle departing employees, including disabling accounts, revoking access, collecting hardware, and archiving data. This must be done immediately to prevent unauthorized access.

8. Which compliance framework specifically governs the protection of credit card holder data?

  • PCI-DSS
  • HIPAA
  • GDPR
  • SOX
PCI-DSS (Payment Card Industry Data Security Standard) applies to any organization that stores, processes, or transmits credit card data. HIPAA covers healthcare data, and GDPR covers EU personal data.

9. What does RPO (Recovery Point Objective) measure?

  • The maximum time to restore a failed system
  • The average time between hardware failures
  • The maximum acceptable amount of data loss measured in time
  • The percentage of uptime guaranteed by a vendor
RPO defines the maximum acceptable amount of data loss, measured in time. An RPO of 4 hours means you can tolerate losing up to 4 hours of data. The maximum time to restore is the RTO (Recovery Time Objective).

10. A network monitoring system sends periodic GET requests to devices to collect interface statistics. Which SNMP method is this?

  • Trap
  • Polling
  • Inform
  • Walk
Polling is when the NMS (Network Management Station) sends periodic Get requests to agents on managed devices (UDP port 161). Traps and Informs are agent-initiated alerts sent to the NMS (UDP port 162).
