4.1 Security Concepts

Network security begins with a solid understanding of foundational principles. These concepts guide every security decision you make, from designing network architectures to choosing authentication methods.

The CIA Triad

The CIA triad represents the three core objectives of information security. Every security control you implement maps back to at least one of these goals.

PrincipleGoalExample Controls
Confidentiality Ensure data is accessible only to authorized parties Encryption, access controls, VPNs, file permissions
Integrity Ensure data has not been altered or tampered with Hashing (SHA-256), digital signatures, checksums, version control
Availability Ensure systems and data are accessible when needed Redundancy, load balancing, backups, fault tolerance, UPS
Exam Tip The exam loves scenario questions about the CIA triad. If a question describes encrypting data, it targets confidentiality. If it asks about verifying data hasn't changed, that's integrity. If it asks about uptime or failover, think availability.

AAA Framework

AAA stands for Authentication, Authorization, and Accounting. It is the backbone of network access control.

  • Authentication — Verifying the identity of a user, device, or system. "Who are you?" Accomplished through usernames/passwords, certificates, biometrics, or tokens.
  • Authorization — Determining what an authenticated user is allowed to do. "What can you access?" Controlled through permissions, group policies, and access control lists.
  • Accounting — Tracking and logging what authenticated users do on the network. "What did you do?" Provides audit trails through logs, session tracking, and usage records.

Common AAA protocols include:

ProtocolPort(s)Key Details
RADIUS UDP 1812/1813 Encrypts only the password; widely used for network access (Wi-Fi, VPN). Combines authentication and authorization in one step.
TACACS+ TCP 49 Encrypts the entire packet; separates authentication, authorization, and accounting. Cisco-developed. Preferred for device administration.

Multifactor Authentication (MFA)

MFA requires two or more different types of authentication factors. Using two passwords is NOT multifactor because they are both the same factor type.

Factor TypeDescriptionExamples
Something you know Knowledge-based secret Password, PIN, security question
Something you have Physical possession Smart card, hardware token, authenticator app, phone (SMS code)
Something you are Biometric trait Fingerprint, retina scan, facial recognition, voice print
Somewhere you are Location-based GPS location, IP address geolocation
Something you do Behavioral biometric Typing pattern, gait analysis, signature dynamics
Common Exam Trap A username + password + PIN is NOT multifactor authentication. Both the password and the PIN are "something you know." True MFA requires factors from different categories (e.g., a password + a fingerprint).

Zero Trust Model

The zero trust security model operates on the principle of "never trust, always verify." Unlike traditional perimeter-based security, zero trust assumes that threats may exist both inside and outside the network.

  • No implicit trust based on network location (internal vs. external)
  • Every access request is fully authenticated, authorized, and encrypted
  • Least privilege access is enforced at all times
  • Microsegmentation limits lateral movement within the network
  • Continuous monitoring and validation of security posture

Defense in Depth

Defense in depth uses multiple layers of security controls so that if one layer fails, others continue to provide protection. Think of it like a castle with a moat, walls, guards, and a locked vault.

Least Privilege

The principle of least privilege dictates that users, systems, and processes should be granted only the minimum access rights needed to perform their job function — nothing more. This limits the damage that can occur from accidents, errors, or unauthorized use.

Role-Based Access Control (RBAC)

RBAC assigns permissions to roles rather than to individual users. Users are then assigned to roles based on their job function. This simplifies administration: when an employee changes roles, you simply change their role assignment instead of modifying individual permissions.

What is the difference between RBAC and DAC?
RBAC (Role-Based Access Control) assigns permissions to roles; users get permissions through role membership. An administrator defines the roles centrally.

DAC (Discretionary Access Control) allows the data owner to decide who has access. The owner can grant or revoke permissions at their discretion (e.g., file sharing permissions in Windows).
What is MAC (Mandatory Access Control)?
MAC uses classification labels (e.g., Top Secret, Secret, Confidential) assigned by a central authority. Users cannot override these labels. Access decisions are based on the label of the resource and the clearance level of the user. Used in military/government environments.

Certificate-Based Authentication & PKI

Public Key Infrastructure (PKI) is a framework for managing digital certificates and public/private key pairs. It enables secure communication and identity verification.

  • Certificate Authority (CA) — A trusted entity that issues digital certificates. The CA verifies identity before issuing a certificate.
  • Digital Certificate — An electronic document that binds a public key to an identity. Contains the subject name, public key, issuer (CA), validity period, and a digital signature.
  • Certificate Revocation List (CRL) — A list of certificates that have been revoked before expiration.
  • OCSP (Online Certificate Status Protocol) — A real-time alternative to CRLs for checking certificate validity.

Encryption Types

TypeHow It WorksSpeedExamplesUse Cases
Symmetric Same key for encryption and decryption Fast AES, DES, 3DES, Blowfish Bulk data encryption, disk encryption, VPN tunnels
Asymmetric Paired public and private keys; one encrypts, the other decrypts Slower RSA, ECC, Diffie-Hellman, DSA Key exchange, digital signatures, certificate-based auth, email encryption
How They Work Together In practice, asymmetric encryption is used to securely exchange a symmetric session key. Then symmetric encryption handles the bulk data transfer because it's much faster. This hybrid approach is used in TLS/SSL, IPSec, and most VPNs.

4.2 Common Network Attacks

Understanding attack types is essential for both the exam and real-world network defense. You need to know how each attack works, what it targets, and how to mitigate it.

Denial-of-Service (DoS) and Distributed Denial-of-Service (DDoS)

DoS attacks aim to make a network resource unavailable by overwhelming it with traffic or exploiting a vulnerability. DDoS attacks use multiple compromised systems (a botnet) to launch the attack simultaneously.

  • SYN Flood — The attacker sends a massive number of TCP SYN packets but never completes the three-way handshake. The target's connection table fills up with half-open connections, preventing legitimate users from connecting.
  • Amplification Attack — The attacker sends small requests to a third-party server (e.g., DNS, NTP) with the source IP spoofed to the victim's address. The server replies with much larger responses directed at the victim, amplifying the attack volume.
  • Reflection Attack — Similar to amplification, the attacker bounces traffic off legitimate servers. The victim receives the reflected responses. Often combined with amplification for maximum impact.
Key Distinction A DoS attack comes from a single source. A DDoS attack comes from many distributed sources (botnet). DDoS is much harder to mitigate because you cannot simply block one IP address.

Man-in-the-Middle (MITM) / On-Path Attacks

In an on-path attack, the attacker secretly intercepts and possibly alters communication between two parties who believe they are communicating directly. The attacker can eavesdrop on traffic, steal credentials, or inject malicious content.

  • Can occur at multiple layers (Layer 2 with ARP spoofing, Layer 7 with SSL stripping)
  • Mitigated by encryption (TLS/SSL), certificate validation, and network monitoring

ARP Spoofing / ARP Poisoning

The attacker sends falsified ARP (Address Resolution Protocol) messages on a local network, linking the attacker's MAC address with the IP address of a legitimate host (like the default gateway). Traffic intended for the gateway is then redirected through the attacker's machine.

  • Enables man-in-the-middle attacks on LANs
  • Mitigation: Dynamic ARP Inspection (DAI), static ARP entries, network segmentation

DNS Poisoning / DNS Spoofing

The attacker corrupts the DNS cache so that domain name queries return an incorrect IP address, redirecting users to malicious websites. This can be done by intercepting DNS queries or compromising a DNS server.

  • Users may visit fake banking or login sites without realizing it
  • Mitigation: DNSSEC (DNS Security Extensions), encrypted DNS (DoH/DoT), monitoring DNS logs

VLAN Hopping

An attacker gains access to traffic on a VLAN they are not assigned to. Two primary methods:

  • Switch Spoofing — The attacker configures their NIC to act as a trunk port, negotiating a trunk link with the switch using DTP (Dynamic Trunking Protocol). This gives access to all VLANs on the trunk.
  • Double Tagging — The attacker sends a frame with two 802.1Q VLAN tags. The first switch strips the outer tag, and the inner tag routes the frame to the target VLAN.

Mitigation: Disable DTP on all access ports (switchport mode access), set native VLAN to an unused VLAN, enable VLAN pruning.

Rogue DHCP Server

An unauthorized DHCP server on the network hands out incorrect IP configurations to clients. This can redirect traffic through an attacker-controlled gateway (enabling MITM attacks) or cause denial of service by assigning invalid addresses.

Mitigation: DHCP snooping — configures switch ports as trusted (where legitimate DHCP servers reside) or untrusted (blocks DHCP offers from those ports).

Evil Twin

An attacker sets up a rogue wireless access point with the same SSID (and sometimes the same MAC address) as a legitimate AP. Unsuspecting users connect to the evil twin, and the attacker can intercept all their traffic.

Mitigation: 802.1X authentication, wireless intrusion prevention systems (WIPS), user education, certificate-based wireless authentication.

Social Engineering Attacks

  • Phishing — Fraudulent emails that appear to come from a trusted source, tricking the recipient into clicking malicious links or providing credentials.
  • Spear Phishing — Targeted phishing aimed at specific individuals or organizations, often using personal details to appear convincing.
  • Vishing — Voice phishing; social engineering conducted over the phone.
  • Smishing — Phishing via SMS text messages.
  • Tailgating / Piggybacking — An unauthorized person follows an authorized individual through a secure door or entry point without scanning their own credentials.
  • Shoulder Surfing — Watching someone enter credentials or sensitive information over their shoulder.

Malware Types

  • Ransomware — Encrypts the victim's files and demands payment for the decryption key. Can spread laterally across a network.
  • Virus — Malicious code that attaches itself to a legitimate program. Requires user action to execute.
  • Worm — Self-replicating malware that spreads across networks without user interaction.
  • Trojan — Malware disguised as legitimate software. Does not self-replicate but provides backdoor access.
  • Rootkit — Hides deep within the OS to maintain persistent, privileged access while evading detection.
  • Spyware — Secretly monitors user activity (keystrokes, browsing, etc.) and reports it to the attacker.

Insider Threats

Threats originating from within the organization — employees, contractors, or partners with legitimate access. Insider threats can be intentional (data theft, sabotage) or unintentional (accidental data exposure, falling for phishing). They are among the hardest threats to detect because the attacker already has valid credentials.

Password Attacks

  • Brute Force — Systematically tries every possible combination until the correct password is found. Effective against short or weak passwords.
  • Dictionary Attack — Uses a pre-built list of common words and passwords. Faster than brute force for common passwords.
  • Rainbow Table — A precomputed table of password hashes. The attacker compares captured hashes against the table for instant lookups. Mitigated by salting (adding random data to each password before hashing).
  • Credential Stuffing — Uses username/password pairs stolen from one breach to attempt logins at other services, exploiting password reuse.

Deauthentication Attacks

The attacker sends forged deauthentication frames (802.11 management frames) to a wireless client or access point, disconnecting the client. This can be used to force a client to reconnect to an evil twin AP or to disrupt service.

Mitigation: 802.11w (Management Frame Protection), WPA3 (which mandates protected management frames).

4.3 Network Hardening

Network hardening is the process of reducing the attack surface by eliminating unnecessary services, securing configurations, and applying protective measures. A hardened network is significantly more resistant to attacks.

Disabling Unused Ports and Services

Every open port and running service is a potential entry point for an attacker. Hardening involves:

  • Shutting down unused switch ports (shutdown command on unused interfaces)
  • Disabling unnecessary network services (Telnet, HTTP management interfaces, SNMP v1/v2 if not needed)
  • Removing or disabling unused software and protocols from servers and network devices
  • Performing regular port scans to identify unexpected open ports

Changing Default Credentials

Many network devices ship with well-known default usernames and passwords (e.g., admin/admin, admin/password). Attackers maintain databases of default credentials. Always change defaults immediately upon deployment.

Critical Security Practice Default credentials are one of the most common causes of network breaches. This applies to routers, switches, firewalls, wireless APs, IoT devices, and management interfaces. Change the username where possible, and use strong, unique passwords.

Firmware Updates and Patch Management

  • Keep firmware on all network devices (routers, switches, APs, firewalls) current
  • Apply security patches promptly to close known vulnerabilities
  • Establish a patch management policy with testing procedures before deployment
  • Subscribe to vendor security advisories and CVE notifications
  • Maintain a current inventory of all devices and their firmware versions

Disabling Unnecessary Protocols

Protocols that are not needed should be disabled to reduce attack surface:

Protocol to DisableWhySecure Alternative
Telnet (TCP 23)Sends credentials in cleartextSSH (TCP 22)

MAC Filtering

MAC filtering restricts network access based on the hardware (MAC) address of the connecting device. The switch or access point maintains a whitelist of allowed MAC addresses.

  • Provides a basic layer of access control, especially on wireless networks
  • Limitation: MAC addresses can be easily spoofed, so MAC filtering should never be the sole security mechanism
  • Best used as one layer in a defense-in-depth strategy

802.1X (Port-Based Network Access Control)

802.1X is an IEEE standard for port-based NAC. It prevents devices from accessing the network until they authenticate. Three key components:

ComponentRoleExample
Supplicant The client device requesting access Laptop, phone, workstation
Authenticator The network device controlling access (the gatekeeper) Switch port or wireless AP
Authentication Server Validates credentials and grants/denies access RADIUS server
+-------------+ +----------------+ +------------------+ | Supplicant | <---> | Authenticator | <---> | Authentication | | (Client) | EAPoL | (Switch / AP) | RADIUS | Server | +-------------+ +----------------+ +------------------+ 1. Client connects to port (port is BLOCKED) 2. Switch requests identity from client 3. Client sends credentials via EAP over LAN (EAPoL) 4. Switch forwards credentials to RADIUS server 5. RADIUS authenticates → sends Accept/Reject 6. If accepted, switch opens the port
Exam Tip 802.1X uses EAP (Extensible Authentication Protocol) for the authentication framework. Common EAP types include EAP-TLS (certificate-based, very secure), PEAP (uses a server certificate to create a TLS tunnel), and EAP-FAST (Cisco's method using a PAC).

DHCP Snooping

DHCP snooping is a Layer 2 security feature that filters untrusted DHCP messages and builds a binding table of valid IP-to-MAC mappings.

  • Trusted ports — Connected to legitimate DHCP servers; allow DHCP offers and acknowledgments
  • Untrusted ports — Connected to clients; only DHCP requests are allowed. DHCP offers from these ports are dropped.
  • Prevents rogue DHCP server attacks
  • The binding table is also used by Dynamic ARP Inspection and IP Source Guard

Dynamic ARP Inspection (DAI)

DAI validates ARP packets on the network using the DHCP snooping binding table. It intercepts ARP replies on untrusted ports and verifies that the IP-to-MAC mapping is legitimate. Invalid ARP packets are dropped, preventing ARP spoofing attacks.

Segmentation and Microsegmentation

  • Network Segmentation — Dividing the network into smaller segments (VLANs, subnets) to contain breaches and limit lateral movement. A compromised host in one segment cannot easily reach hosts in another.
  • Microsegmentation — Granular segmentation at the workload or application level, often implemented through software-defined networking (SDN). Each workload or server has its own security policies, even within the same subnet.

Privileged Access Management (PAM)

PAM controls and monitors access to privileged accounts (admin, root, service accounts). Key practices include:

  • Storing privileged credentials in a secure vault (not in scripts or spreadsheets)
  • Requiring check-out/check-in of privileged credentials with session recording
  • Just-in-time (JIT) access — granting elevated privileges only when needed and for a limited time
  • Auditing and logging all privileged access sessions

4.4 Firewalls & ACLs

Firewalls are the primary perimeter defense for any network. Combined with access control lists, they determine what traffic is permitted and denied based on defined rules.

Firewall Types

TypeHow It WorksPros / Cons
Stateless (Packet Filtering) Examines each packet individually based on source/destination IP, port, and protocol. No awareness of connection state. Fast but cannot track TCP sessions or detect complex attacks. Each packet is evaluated in isolation.
Stateful Tracks the state of active connections. Packets are evaluated in the context of their connection (new, established, related). More secure than stateless. Can determine if a packet is part of a legitimate session. Most common firewall type.
NGFW (Next-Generation Firewall) Combines stateful inspection with deep packet inspection (DPI), application awareness, IPS, and threat intelligence. Can identify and control applications (e.g., block Facebook but allow LinkedIn). Inspects encrypted traffic. Higher cost.
UTM (Unified Threat Management) All-in-one security appliance: firewall + IDS/IPS + antivirus + content filter + VPN + anti-spam. Convenient for small-to-medium businesses. Single point of management but also single point of failure.
WAF (Web Application Firewall) Specifically protects web applications by filtering HTTP/HTTPS traffic. Operates at Layer 7. Blocks SQL injection, cross-site scripting (XSS), and other web attacks. Does not replace a network firewall.

Implicit Deny

Implicit deny is a fundamental firewall principle: any traffic that is not explicitly permitted by a rule is automatically denied. This means that at the end of every ACL or firewall rule set, there is an invisible "deny all" rule. You must specifically create rules for the traffic you want to allow.

Exam Favorite If you configure a firewall with no rules, ALL traffic will be blocked due to the implicit deny. This is a very commonly tested concept. Always remember: if a rule set does not explicitly permit the traffic, it is denied.

Access Control Lists (ACLs)

ACLs are ordered lists of rules that permit or deny traffic based on criteria such as source/destination IP, port numbers, and protocols. Rules are processed top-down — the first matching rule is applied, and processing stops.

ACL Rule Components

  • Action — permit or deny
  • Protocol — TCP, UDP, ICMP, IP (any)
  • Source — Source IP address (with wildcard mask)
  • Destination — Destination IP address (with wildcard mask)
  • Port — Source and/or destination port number
  • Direction — Applied inbound or outbound on an interface

Example ACL with Explanation

! Extended ACL applied to the inside interface (inbound)
access-list 110 permit tcp 192.168.1.0 0.0.0.255 any eq 443
access-list 110 permit tcp 192.168.1.0 0.0.0.255 any eq 80
access-list 110 permit udp 192.168.1.0 0.0.0.255 any eq 53
access-list 110 permit icmp 192.168.1.0 0.0.0.255 any echo
access-list 110 deny   ip  10.0.0.0 0.255.255.255 any log
access-list 110 deny   ip  any any
!
interface GigabitEthernet0/1
  ip access-group 110 in
LineWhat It Does
permit tcp ... eq 443Allows HTTPS traffic from the 192.168.1.0/24 network to any destination
permit tcp ... eq 80Allows HTTP traffic from the 192.168.1.0/24 network to any destination
permit udp ... eq 53Allows DNS lookups from the internal network

ACL Best Practices Place the most specific rules at the top (processed first). Put frequently matched rules higher for performance. Always include an explicit deny at the end with logging enabled so you can audit blocked traffic. Apply ACLs as close to the source of traffic as possible for extended ACLs.

Firewall Zones

Firewalls organize the network into security zones, each with a different trust level:

  • Trusted (Inside/Internal) — The internal LAN. Highest trust level. Users and internal servers reside here.
  • Untrusted (Outside/External) — The internet or any uncontrolled network. Lowest trust level. Treated as hostile.
  • DMZ (Demilitarized Zone) / Screened Subnet — A semi-trusted zone between internal and external networks. Hosts public-facing servers (web, email, DNS) that need to be accessible from the internet but are isolated from the internal network.
INTERNET | +-------+-------+ | Firewall | | (Outside Int) | +---+-------+---+ | | +-----+ +-+------+ | DMZ | | Inside | +-----+ +--------+ Web Server Internal LAN Mail Server Workstations DNS Server File Servers Traffic Flow Rules: Inside → DMZ: Allowed (controlled) Inside → Outside: Allowed (with NAT) Outside → DMZ: Allowed (specific ports only) Outside → Inside: DENIED (implicit deny) DMZ → Inside: DENIED (prevents compromised DMZ host from reaching LAN)

Rule-Based Management

  • Document every firewall rule with a justification and an owner
  • Review rules periodically to remove obsolete or overly permissive entries
  • Use change management procedures before modifying firewall rules
  • Test rule changes in a staging environment when possible
  • Follow the principle of least privilege: only allow what is necessary

Geofencing

Geofencing restricts or permits access based on geographic location. A firewall or security system can block connections from specific countries or regions. Commonly used to block traffic from regions where the organization has no business presence, reducing exposure to foreign threat actors.

Content Filtering

Content filtering inspects web traffic to block access to inappropriate, dangerous, or policy-violating content categories (malware sites, gambling, social media during business hours). Can be implemented on firewalls, proxy servers, or dedicated content filtering appliances. Often uses URL categorization databases.

4.5 VPN & Remote Access

Virtual Private Networks create encrypted tunnels over public networks, enabling secure remote connectivity. Understanding VPN types and protocols is essential for both the exam and real-world network administration.

VPN Types

VPN TypeDescriptionUse Case
Site-to-Site Connects two entire networks (e.g., branch office to headquarters). The VPN tunnel is established between two VPN gateways (routers/firewalls). Individual clients are unaware of the VPN. Connecting branch offices to HQ over the internet. Always-on connection.
Client-to-Site (Remote Access) A single remote user connects to the corporate network using VPN client software. The tunnel is established between the user's device and the VPN gateway. Remote workers connecting to the office. Telecommuting.
Clientless VPN No VPN client software is needed. The user connects via a web browser using SSL/TLS. Access is typically limited to web-based applications, file shares, and email. Quick access from unmanaged devices (kiosks, personal computers). Limited application support.

IPSec (Internet Protocol Security)

IPSec is a suite of protocols that provides encryption, integrity, and authentication at the network layer (Layer 3). It is the most common protocol for site-to-site VPNs.

IPSec Components

ComponentFunctionDetails
AH (Authentication Header) Provides integrity and authentication Verifies that the packet was not altered in transit. Does NOT encrypt data. Protocol number 51.
ESP (Encapsulating Security Payload) Provides encryption, integrity, and authentication Encrypts the payload for confidentiality AND provides integrity checking. Protocol number 50. Most commonly used.
IKE (Internet Key Exchange) Negotiates security associations and exchanges keys IKE Phase 1: establishes a secure channel (ISAKMP SA). IKE Phase 2: negotiates the IPSec SA for actual data transfer. Uses UDP port 500 (and 4500 for NAT traversal).

IPSec Modes

ModeWhat Is EncryptedUse Case
Transport Mode Only the payload is encrypted; the original IP header remains intact Host-to-host communication (e.g., two servers communicating directly). Lower overhead.
Tunnel Mode The entire original packet (header + payload) is encrypted and encapsulated with a new IP header Site-to-site VPNs. The most common mode. Hides the original source and destination IPs.
Transport Mode: [Original IP Header] [ESP/AH Header] [Encrypted Payload] (unchanged) Tunnel Mode: [New IP Header] [ESP/AH Header] [Encrypted Original IP Header + Payload] (VPN gateway IPs) (entire original packet is hidden)
Exam Tip If a question mentions encrypting traffic between two VPN gateways (site-to-site), the answer is tunnel mode. If it mentions encrypting between two individual hosts, think transport mode. ESP is preferred over AH because ESP provides encryption (confidentiality), while AH only provides integrity and authentication.

SSL/TLS VPN

SSL/TLS VPNs use the TLS protocol (typically over TCP 443) to create encrypted tunnels. Because they use the same port as HTTPS, they pass through most firewalls and NAT devices without issues.

  • Easier to deploy than IPSec — no special client software for clientless mode
  • Works well through firewalls and proxy servers (port 443 is almost always open)
  • Can provide full network access (with a client) or application-level access (clientless)
  • Common in remote access / client-to-site deployments

Split Tunnel vs. Full Tunnel

TypeHow It WorksProsCons
Split Tunnel Only traffic destined for the corporate network goes through the VPN. Internet traffic goes directly to the internet via the user's local connection. Reduces VPN bandwidth usage, faster internet browsing for the user Internet traffic bypasses corporate security controls; potential data leakage
Full Tunnel ALL traffic (corporate and internet) is routed through the VPN tunnel to the corporate network. All traffic is inspected by corporate security (firewall, content filter, IDS) Higher bandwidth usage on VPN, slower internet experience for users
Security vs. Performance Trade-off Full tunnel is more secure because all traffic passes through corporate security controls. Split tunnel is more efficient but creates a risk: the user's device is simultaneously connected to the corporate network and the open internet, potentially acting as a bridge for attacks.

DMVPN (Dynamic Multipoint VPN)

DMVPN allows multiple sites to communicate directly (spoke-to-spoke) without routing all traffic through a central hub. It dynamically builds IPSec tunnels between sites on demand.

  • Reduces latency for spoke-to-spoke communication
  • Simplifies configuration — adding a new site doesn't require reconfiguring every other site
  • Uses NHRP (Next Hop Resolution Protocol) to discover tunnel endpoints
  • Ideal for large enterprise networks with many branch offices

Always-On VPN

The VPN connection is established automatically whenever the device is powered on and connected to a network. The user cannot disconnect or bypass the VPN. This ensures that all traffic is always protected and passes through corporate security controls. Common in organizations with strict security requirements.

Remote Access Methods

Remote Desktop Protocols

  • RDP (Remote Desktop Protocol) — Microsoft protocol (TCP 3389). Provides full graphical remote access to a Windows desktop. Should be used over a VPN, never exposed directly to the internet.
  • VNC (Virtual Network Computing) — Platform-independent remote desktop protocol (TCP 5900). Traffic is not encrypted by default; use over an SSH tunnel or VPN.

Out-of-Band (OOB) Management

Out-of-band management provides a separate, dedicated management path to network devices that does not rely on the production network. If the primary network goes down, you can still access devices for troubleshooting and recovery.

  • Console port (serial) access via a console server
  • Dedicated management VLAN or network
  • Cellular/modem connection for emergency access

Jump Server / Jump Box

A jump server is a hardened, dedicated server that acts as an intermediary access point between a trusted network and a less-trusted environment (like a DMZ or server VLAN). Administrators connect to the jump server first, then connect from the jump server to the target device. This:

  • Centralizes access control and audit logging
  • Reduces the attack surface by limiting direct access to critical systems
  • Provides a single point to enforce MFA and session monitoring

SSH Tunneling / Port Forwarding

SSH tunneling creates an encrypted tunnel for forwarding traffic from one port to another through an SSH connection. This allows you to securely access services that don't natively support encryption.

# Local port forwarding: access remote service via local port
# This forwards local port 8080 to remote-db-server:3306 through ssh-server
ssh -L 8080:remote-db-server:3306 user@ssh-server

# Now connect to localhost:8080 to securely reach the database
  • Local Port Forwarding — Forwards a local port through the SSH tunnel to a remote destination
  • Remote Port Forwarding — Makes a local service accessible from the remote side of the SSH tunnel
  • Dynamic Port Forwarding — Creates a SOCKS proxy through the SSH tunnel, routing all traffic dynamically

4.6 Physical Security & Monitoring

Physical security controls protect network equipment and infrastructure from unauthorized physical access, theft, and environmental damage. Monitoring systems detect intrusions and provide the visibility needed for incident response.

Physical Access Controls

Video Surveillance (CCTV)

Closed-circuit television cameras monitor sensitive areas such as server rooms, wiring closets, and building entrances. Provides both deterrence and forensic evidence. Modern IP-based cameras support remote viewing, motion-triggered recording, and integration with access control systems.

Badge Readers and Biometrics

  • Badge/Proximity Card Readers — Use RFID or smart card technology. Employees tap or swipe a badge to gain entry. Logs who accessed what area and when.
  • Biometric Readers — Fingerprint scanners, retina/iris scanners, facial recognition. Much harder to forge than a badge. Consider false acceptance rate (FAR) and false rejection rate (FRR) when evaluating systems.

Mantrap / Security Vestibule

A mantrap (now commonly called a security vestibule) is a small room with two interlocking doors. Only one door can be open at a time. A person must authenticate to enter the first door, then the first door locks before the second door can be opened. This prevents tailgating and ensures only one authenticated individual enters at a time.

Badge Reader Badge Reader | | [Public Area] [Door 1] =[Vestibule]= [Door 2] [Secure Area] (only one door open at a time) 1. Person badges in at Door 1 → enters vestibule 2. Door 1 locks behind them 3. Person badges in at Door 2 → enters secure area 4. If authentication fails at Door 2, person is trapped

Locking Cabinets and Rack Security

  • Server racks should have locking front and rear doors
  • Cable lock slots prevent physical theft of equipment
  • Wiring closets (IDF/MDF rooms) should be locked at all times
  • Key management: track who has keys/combinations; change when personnel leave

Security Guards

Human security guards provide adaptive security that automated systems cannot. They verify identities, respond to incidents, patrol facilities, and enforce policies. Often stationed at building entrances and data center lobbies.

Motion Detection

Motion sensors detect movement in restricted areas and trigger alerts or cameras. Used in server rooms, wiring closets, and after-hours zones. Can be infrared, ultrasonic, or microwave-based.

Asset Tracking and Disposal

  • Asset Tracking — Maintain an inventory of all network equipment with serial numbers, locations, and responsible personnel. Use asset tags (barcode or RFID) for automated tracking.
  • Secure Disposal — When decommissioning equipment, ensure all data is securely erased. Methods include degaussing (for magnetic media), physical destruction (shredding), and cryptographic erasure. Storage media that contained sensitive data must not be simply discarded or recycled without proper sanitization.
Data Destruction Matters Simply deleting files or formatting a drive does NOT destroy data — it can be recovered with forensic tools. For sensitive data, use DoD 5220.22-M wipe standards, physical destruction, or cryptographic erasure (destroy the encryption key, rendering the encrypted data irrecoverable).

Security Information and Event Management (SIEM)

A SIEM system aggregates, correlates, and analyzes log data from multiple sources across the network in real time. It provides a centralized view of security events and enables rapid detection and response to threats.

  • Log Aggregation — Collects logs from firewalls, IDS/IPS, servers, switches, routers, endpoints, and applications into a single platform
  • Correlation — Identifies patterns across multiple log sources that might indicate an attack (e.g., failed login on server + port scan from same IP + firewall alert)
  • Alerting — Generates real-time alerts when predefined rules or thresholds are triggered
  • Reporting — Produces compliance reports and dashboards for security teams and auditors
  • Retention — Stores logs for the required retention period (often mandated by regulations)

Log Management and Review

Effective log management is critical for troubleshooting, forensics, and compliance:

  • Centralize logs using syslog servers (UDP 514) or SIEM platforms
  • Synchronize clocks across all devices using NTP so log timestamps are consistent
  • Review logs regularly — not just after incidents
  • Protect log integrity — logs should be write-once or sent to a separate, secured system to prevent tampering
  • Define retention policies based on organizational and regulatory requirements
Exam Tip NTP (Network Time Protocol, UDP 123) synchronization is essential for log correlation. If device clocks are out of sync, reconstructing the timeline of a security incident becomes extremely difficult or impossible.

Packet Capture

Packet capture (pcap) records the raw network traffic for detailed analysis. Useful for troubleshooting, forensic investigation, and verifying that security controls are working.

  • Tools: Wireshark (GUI), tcpdump (CLI), network TAPs, SPAN/mirror ports
  • SPAN (Switched Port Analyzer) — Configures a switch to copy traffic from one or more ports to a monitoring port for capture
  • Network TAP — A physical device inserted into a network link that copies all traffic to a monitoring port without affecting the original traffic flow

IDS vs. IPS

Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) monitor network traffic for malicious activity. The key difference is in their response capability.

FeatureIDS (Detection)IPS (Prevention)
ActionDetects and alerts on threats (passive)Detects, alerts, AND blocks threats (active/inline)
PlacementConnected to a SPAN/mirror port (out-of-band)Placed inline — traffic passes through it
Impact on TrafficNo impact — does not alter traffic flowCan block, drop, or modify malicious packets
LatencyNone (passive monitoring)Introduces slight latency (inline processing)
RiskMay miss blocking an attack (only alerts)False positives can block legitimate traffic

Detection Methods

  • Signature-Based — Compares traffic against a database of known attack patterns (signatures). Effective against known threats. Cannot detect new (zero-day) attacks. Requires regular signature updates.
  • Anomaly-Based (Behavioral) — Establishes a baseline of normal network behavior and alerts when traffic deviates significantly from that baseline. Can detect unknown/zero-day attacks. Higher false positive rate.
  • Heuristic-Based — Uses rules, algorithms, and experience-based analysis to identify potentially malicious behavior. Falls between signature and anomaly-based. Can detect variants of known attacks.
NIDS vs. HIDS — What is the difference?
NIDS (Network-Based IDS) monitors network traffic at strategic points (e.g., network perimeter). Analyzes packets flowing across the network.

HIDS (Host-Based IDS) is installed on individual hosts/servers. Monitors system calls, file integrity, log files, and registry changes on that specific host. Protects the endpoint rather than the network.
What is the crossover error rate (CER)?
The CER (also called the Equal Error Rate / EER) is the point at which the False Acceptance Rate (FAR) equals the False Rejection Rate (FRR) in a biometric system. A lower CER indicates a more accurate biometric system. It is used to compare the overall accuracy of different biometric devices.

Port Security

Port security is a Layer 2 feature on switches that restricts which MAC addresses can connect to a given port. It limits the number of MAC addresses allowed on a port and defines what happens when a violation occurs.

  • Static MAC — Manually configure allowed MAC addresses on each port
  • Sticky MAC — The switch dynamically learns and saves MAC addresses; they persist across reboots
  • Violation Modes:
    • Protect — Drops traffic from unknown MACs; no alert generated
    • Restrict — Drops traffic from unknown MACs; generates a syslog alert and increments violation counter
    • Shutdown — Places the port in error-disabled state (most secure). Port must be manually re-enabled. This is the default on most switches.

Network Access Control (NAC)

NAC solutions evaluate devices before allowing them onto the network. A device must meet security requirements (updated antivirus, current patches, compliant configuration) before being granted access. Non-compliant devices are quarantined or given limited access.

  • Pre-admission NAC — Checks the device BEFORE granting network access
  • Post-admission NAC — Continuously monitors devices after they are on the network; can revoke access if compliance changes
  • Agent-based — Requires software installed on the endpoint for health checks
  • Agentless — Performs checks without requiring software on the endpoint (e.g., via network scanning)
Putting It All Together A comprehensive security posture combines physical controls (locks, cameras, mantraps), logical controls (firewalls, ACLs, IDS/IPS, NAC), and administrative controls (policies, training, auditing). No single control is sufficient — defense in depth is the key principle.

Domain 4 Quiz — Network Security

Test your knowledge of network security concepts. Select the best answer for each question, then submit to see your score.

1. Which component of the CIA triad is MOST directly addressed by implementing a hashing algorithm to verify file downloads?

  • Confidentiality
  • Availability
  • Integrity
  • Authentication
Hashing verifies that data has not been altered or corrupted — this directly addresses integrity. Confidentiality would be addressed by encryption, and availability by redundancy/uptime measures. Authentication is part of AAA, not the CIA triad.

2. An attacker sends spoofed DNS requests to a public DNS server with the source IP set to the victim's address. The DNS server replies with large responses directed at the victim. What type of attack is this?

  • SYN flood
  • DNS amplification attack
  • ARP poisoning
  • Evil twin attack
This describes a DNS amplification attack. The attacker spoofs the victim's IP and sends small queries to a DNS server, which replies with much larger responses to the victim. This amplifies the attack traffic and is a type of DDoS attack.

3. A company wants to prevent unauthorized DHCP servers from assigning IP addresses on their network. Which feature should they enable on their switches?

  • Port security
  • Dynamic ARP Inspection
  • VLAN pruning
  • DHCP snooping
DHCP snooping classifies switch ports as trusted or untrusted. Only trusted ports (connected to legitimate DHCP servers) are allowed to send DHCP offers. Untrusted ports that attempt to send DHCP offers have those packets dropped, preventing rogue DHCP servers.

4. In an 802.1X deployment, what is the role of the authenticator?

  • The network device (switch or AP) that controls port access
  • The RADIUS server that validates credentials
  • The client device requesting network access
  • The certificate authority that issues digital certificates
In 802.1X, the authenticator is the network device (switch or wireless AP) that acts as the gatekeeper. It blocks access until the supplicant (client) authenticates through the authentication server (RADIUS). The authenticator forwards credentials but does not validate them itself.

5. What is the PRIMARY difference between an IDS and an IPS?

  • An IDS uses signatures while an IPS uses anomaly detection
  • An IDS operates at Layer 3 while an IPS operates at Layer 7
  • An IDS only alerts on threats while an IPS can actively block them
  • An IDS is hardware-based while an IPS is software-based
The primary difference is that an IDS passively monitors traffic and generates alerts, while an IPS is placed inline and can actively block or drop malicious traffic. Both can use signature-based, anomaly-based, or heuristic detection methods.

6. A remote employee uses a VPN where only traffic destined for the corporate network is sent through the encrypted tunnel, while internet browsing goes directly through their home ISP. What type of VPN configuration is this?

  • Full tunnel
  • Split tunnel
  • Site-to-site VPN
  • Always-on VPN
Split tunnel sends only corporate-destined traffic through the VPN while allowing internet traffic to go directly through the user's local ISP. A full tunnel would route ALL traffic through the VPN, including general internet browsing.

7. Which firewall type combines stateful inspection, deep packet inspection, application awareness, and integrated intrusion prevention?

  • Stateless packet filter
  • Web Application Firewall (WAF)
  • Stateful firewall
  • Next-Generation Firewall (NGFW)
A Next-Generation Firewall (NGFW) combines traditional stateful inspection with deep packet inspection, application-level awareness (Layer 7), and integrated IPS capabilities. A standard stateful firewall does not provide application awareness or DPI.

8. A security administrator needs to ensure that a compromised web server in the DMZ cannot be used to attack the internal network. Which firewall rule best accomplishes this?

  • Deny all traffic from the DMZ to the internal network
  • Permit all traffic from the DMZ to the internal network
  • Deny all traffic from the internet to the DMZ
  • Permit all traffic from the internal network to the DMZ
A core DMZ security principle is that DMZ-to-internal traffic should be denied. If a server in the DMZ is compromised, this rule prevents the attacker from using it as a pivot point to reach internal resources. Traffic from the inside to the DMZ may be allowed, but never the reverse.

9. Which IPSec component provides both encryption and integrity verification for VPN traffic?

  • AH (Authentication Header)
  • IKE (Internet Key Exchange)
  • ESP (Encapsulating Security Payload)
  • GRE (Generic Routing Encapsulation)
ESP (Encapsulating Security Payload) provides confidentiality (encryption), integrity, and authentication. AH provides integrity and authentication but does NOT encrypt data. IKE is used for key negotiation, not data protection. GRE is a tunneling protocol with no built-in security.

10. A small room with two interlocking doors is installed at the entrance to a data center. Only one door can be open at a time, and a person must authenticate before each door opens. What is this physical security control called?

  • Faraday cage
  • Mantrap / Security vestibule
  • Air gap
  • Honeypot
A mantrap (security vestibule) is a small room with two interlocking doors where only one can be open at a time. It prevents tailgating by ensuring only one authenticated person passes through at a time. A Faraday cage blocks electromagnetic signals, an air gap is a network isolation method, and a honeypot is a decoy system.
